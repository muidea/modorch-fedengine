# 配置与状态契约

## FE-CONFIG-001

触发：宿主选择 TOML、准备文件路径和 SecretRef，再注册/启动。
保证：Config::load/validate 保持当前 DTO，不相对配置文件重定位；相对路径沿用进程工作目录语义。宿主可显式准备绝对路径，库不改变 CWD/环境、日志或信号。不同实例独立分配管理文件、临时目录、端口、配置和凭据来源。源 file 引用仅解析至各自凭据目录；PGWire 用户口令仍为环境变量引用，缺失/空值明确失败，不改用默认凭据。

## FE-STATE-001

触发：同进程两个实例打开同管理文件、路径别名或并发新建。
保证：仅一个实例获准，失败方保留明确 already owned 主因并清理自己的资源。占用随实际根连接保留，包括失败补偿和 StopIncomplete；正常排空后可重开。已有文件/父目录符号链接规范路径覆盖，Unix 还检查设备号/inode 硬链接。原生 DuckDB 跨进程文件锁继续生效。
边界：宿主不在运行中移动、替换或删除文件/WAL；不保证绕过 FedEngine 的原生进程内连接、所有文件系统或非 Unix 硬链接行为。

## FE-STATE-002

触发：宿主/仓库/包更名、同版本重启或不支持的存储版本。
保证：保持现有物理文件、SecretRef、凭据内容、持久化修订和对象身份。不重命名为新空库，不静默升级/降级/清空/修复。当前开发阶段只维护当前模型，不增加历史迁移链。发布前备份和匹配版本回退由宿主管理；实际存储模型变化须单独确定验收范围。

具体字段、保护及复现见[配置所有权](../docs/configuration-ownership.md)。
