# 0.1.0 开发交付与发布边界

当前版本是 **development / publish=false**。该说明描述可构建源码的交付内容与发布条件，不宣称已提交、推送、打 Tag、发布 crates.io 或通过远程 CI。源码修订必须由实际提交固定，不能用本文日期或此前远程 HEAD 替代。

## 组件与版本

| 对象 | 当前约束 |
|---|---|
| 对外包 | `modorch-fedengine` 0.1.0；Rust crate `modorch_fedengine` |
| 内部组件 | `modorch-fedengine-*`，同一 workspace 0.1.0 |

| 开发支持 | 根 `modorch-fedengine-workspace`、`tests/support/host` 与 `fedengine-test-host` example，仅供测试 |

| 业务库 Contract / Skill | 1.1.1 / `modorch-fedengine-integration` 1.1.3；Skill 快照同时约束框架与当前 Facade 源码指纹 |

Cargo 的 Facade package metadata 维护 status、业务 Contract revision、框架版本/revision 及未开放能力标志。可用 `cargo metadata --locked --offline --format-version 1` 查看实际解析，不只比对 manifest 文字。

## 当前交付范围

- 纯工厂注册 Bundle，返回实际 IDs 与资源建议，宿主显式选择并拥有 Application/Runtime/预算/日志/信号。
- PgServer/ManagedServer 的 PG+HTTP、PG-only、HTTP-only，保留现有管理与协议/SQL 子集；Handle 只读真实健康、代际、指标与保守可用地址。
- 开发测试宿主通过 dev-dependency 复用同一 Bundle；独立 workspace 样例经仓库外消费者验证。服务生命周期和部署统一归 magicDataHub。
- 生命周期、路径、管理文件唯一占用、凭据目录和持久身份保护；原有 PG/MySQL CRUD、跨源只读 JOIN 和受控单源 DDL。

受控 QueryClient/ManagementClient（DDL 通过 QueryClient）见[接入说明](../in-process-clients.md)。EmbeddedCore仍未开放。magicDataHub应用由宿主仓库交付并单独验收，本库回归不保证MQTT/FedEngine联合容量或故障覆盖；生产规模/长期/完整故障认证继续专项验收。精确协议与版本边界以[能力矩阵](../library-regression.md)和[业务契约](../../contracts/README.md)为准。

## 分发前的验证与操作

1. 静态文档/契约/元数据检查、实际本地契约与完整 workspace 测试、fmt/Clippy、Rustdoc 及 doctest、开发测试宿主/Web smoke。
2. 仓库外独立锁消费者验证唯一框架来源与 Facade 公共边界；一次性 PG/MySQL 回归覆盖受支持版本，不使用业务 DSN。
3. Skill 指纹匹配和 schema/link 校验；打包列表检查 README、源码与必要文件，审查无运行状态或密钥。包清单可检查不等于可向 registry 发布，内部依赖发布闭包尚需单独规划。
4. 审查完整未提交变更并形成可构建提交。Git 消费必须固定包含此接口的实际 revision，再在外部干净环境验收；不能宣称旧提交已有新 API。
5. 真正提交/推送、创建 Tag/Release 或发布前按用户授权执行。crates.io 发布须先规划所有内部 path 依赖的 registry 身份/顺序、发布策略和干净消费者，不在本轮静默启用。

部署切换遵循[迁移与备份规则](../migration/fedengine-to-modorch-fedengine.md)。不新增历史存储迁移链，版本不匹配明确拒绝。实际命令结果记录于外部生态核对清单，临时日志、报告、截图和机器快照不归档到业务仓库。
